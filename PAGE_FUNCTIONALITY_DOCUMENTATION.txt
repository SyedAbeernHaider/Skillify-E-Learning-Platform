1.1 HOME PAGE (/)
-----------------
Route: /
Component: frontend/src/pages/Home.jsx

FRONTEND FUNCTIONALITY:
- Displays hero section with platform introduction
- Shows featured courses carousel
- Displays statistics (total students, courses, instructors)
- Shows category cards for course browsing
- Testimonials section
- Call-to-action buttons for signup/login

BACKEND INTEGRATION:
- API: GET /api/student/courses
- Controller: studentController.getAllCourses()
- Fetches all published courses for display
- No authentication required
- Returns course data: title, thumbnail, price, instructor, rating

DATA FLOW:
1. Component mounts → useEffect triggers
2. Calls getAllCourses() from studentService
3. Backend queries Course model with status: 'published'
4. Returns course array to frontend
5. Component renders courses in grid/carousel

1.6 CART PAGE (/cart)
--------------------

BACKEND INTEGRATION:

2.1 LOGIN PAGE (/login)
----------------------
Route: /login
Component: frontend/src/pages/Login.jsx

FRONTEND FUNCTIONALITY:
- Email and password input fields
- Remember me checkbox
- Forgot password link
- Social login buttons (Google, Facebook)
- Form validation
- Error message display
- Redirect to appropriate dashboard after login

BACKEND INTEGRATION:
- API: POST /api/auth/login
- Controller: authController.login()
- Validates credentials against User model
- Returns JWT token and user data

DATA FLOW:
1. User submits login form
2. Frontend validates input fields
3. Calls login API with email and password
4. Backend finds user by email
5. Compares password hash using bcrypt
6. Generates JWT token with user ID and role
7. Returns token and user object
8. Frontend stores token in sessionStorage
9. Stores user data in Redux
10. Redirects based on role: /student/dashboard, /instructor/dashboard, /admin/dashboard

3.6 TAKE QUIZ PAGE (/student/quiz/:courseId/:sectionIndex/:lectureIndex)
------------------------------------------------------------------------
Route: /student/quiz/:courseId/:sectionIndex/:lectureIndex
Component: frontend/src/pages/Student/TakeQuiz.jsx
Protected: Yes (Student role)

FRONTEND FUNCTIONALITY:
- Displays quiz questions one by one
- Multiple choice, true/false question types
- Timer for timed quizzes
- Submit quiz button
- Review answers option
- Score display after submission

BACKEND INTEGRATION:
- API: GET /api/student/quizzes/course/:courseId/section/:sectionIndex
- API: POST /api/student/courses/:courseId/sections/:sectionIndex/quiz/attempt
- Controller: studentQuizController.getQuizBySection()
- Controller: studentController.submitEmbeddedQuiz()

DATA FLOW:
1. Component loads quiz by course and section
2. Backend finds quiz in course structure
3. Returns quiz questions (without correct answers)
4. Student answers all questions
5. Submits quiz with answers array
6. Backend calculates score:
   - Compares student answers with correct answers
   - Calculates percentage
   - Determines pass/fail (passing score: 70%)
7. Creates QuizResult document
8. If passed, may award badge
9. Updates enrollment progress
10. Returns score and result to frontend
11. Frontend displays score and feedback

6.2 AUTHENTICATION FLOW
-----------------------

LOGIN PROCESS:
1. User enters credentials
2. Frontend validates input
3. POST /api/auth/login with email and password
4. Backend finds user by email
5. Compares password hash
6. Generates JWT token with payload: { id, role }
7. Returns { token, user: { id, name, email, role } }
8. Frontend stores token in sessionStorage
9. Stores user in Redux store
10. Redirects based on role

LOGOUT PROCESS:
1. User clicks logout
2. Frontend clears sessionStorage
3. Clears Redux store
4. Redirects to /login

PROTECTED ROUTES:
1. User accesses protected route
2. ProtectedRoute component checks authentication
3. Reads token from sessionStorage
4. If no token, redirects to /login
5. If token exists, checks user role
6. If role matches allowedRoles, renders component
7. If role doesn't match, redirects to appropriate dashboard

TOKEN VERIFICATION:
1. Every API request includes Authorization header
2. Backend middleware (protect) extracts token
3. Verifies token using JWT secret
4. Decodes token to get user ID
5. Finds user in database
6. Attaches user to req.user
7. Proceeds to controller


6.3 ENROLLMENT PROCESS
----------------------

STUDENT ENROLLMENT:
1. Student views course detail page
2. Clicks "Enroll Now" button
3. If not logged in, redirects to /login
4. If logged in, calls enrollInCourse(courseId)
5. Backend checks:
   - User is authenticated
   - User is student
   - Course exists and is published
   - Student not already enrolled
6. Creates Enrollment document:
   - studentId, courseId
   - enrolledAt: current date
   - progress: 0
   - completedLectures: []
   - status: 'active'
7. Creates Revenue document:
   - courseId, instructorId, studentId
   - amount: course price
   - date: current date
8. Returns enrollment success
9. Frontend redirects to /student/enrolled
10. Student can access course player


6.4 PROGRESS TRACKING
---------------------

LECTURE COMPLETION:
1. Student watches lecture in course player
2. Clicks "Mark as Complete" checkbox
3. Frontend calls updateProgress(enrollmentId, lectureId)
4. Backend finds Enrollment
5. Adds lectureId to completedLectures array
6. Calculates new progress:
   - totalLectures = count all lectures in course
   - completedCount = completedLectures.length
   - progress = (completedCount / totalLectures) * 100
7. Updates Enrollment.progress
8. Returns updated enrollment
9. Frontend updates progress bar

QUIZ COMPLETION:
1. Student completes quiz
2. Backend calculates score
3. Creates QuizResult document
4. If passed, may award badge
5. Updates enrollment progress
6. Returns result


6.5 CERTIFICATE WORKFLOW
------------------------

ELIGIBILITY CHECK:
1. Student requests certificate
2. Backend verifies:
   - Enrollment.progress === 100
   - All quizzes passed (QuizResult.passed === true)
   - Course has certification enabled
3. Returns eligibility status

CERTIFICATE REQUEST:
1. Student submits certificate request
2. Backend creates Certificate document:
   - studentId, courseId, enrollmentId
   - status: 'pending'
   - requestedAt: current date
3. Notifies instructor/admin

CERTIFICATE APPROVAL:
1. Instructor/Admin reviews request
2. Verifies eligibility
3. Approves request
4. Backend generates PDF certificate
5. Updates Certificate.status to 'approved'
6. Stores certificate file path
7. Student can download

CERTIFICATE DOWNLOAD:
1. Student clicks download
2. Frontend requests certificate file
3. Backend serves PDF file
4. Browser downloads certificate
